## Superficies

- `GET /api/offers/:id` y `PUT /api/offers/:id`.

### La forma del cuerpo del `PUT` (decidida acá, no adivinada)

El contrato no la fijaba, y las dos puntas eligieron distinto: el smoke mandaba
`{extracted_json: {…}}` y la ruta espera **campos planos**. Se ratifica **plano**:

```
PUT /api/offers/:id   { titulo, empresa, ubicacion, modalidad, seniority, resumen,
                        salario, beneficios }
```

- **Texto**: `titulo`, `empresa`, `ubicacion`, `modalidad`, `seniority`, `resumen` — se recortan; un
  vacío **no** cuenta como edición.
- **`salario`**: objeto. **`beneficios`**: lista no vacía.
- Si no viene **ningún** campo editable de los de arriba → `400` con el porqué.
- `200` → `{ ok: true, oferta: {…} }` con la oferta ya mezclada.

**Por qué plano y no `extracted_json`:** el cliente edita **campos**, no una representación de
guardado. Aceptar el objeto anidado ataría la interfaz a cómo se persiste —el día que cambie la
columna, cambia el cliente— y obligaría a mandar la oferta entera para tocar un campo. La mezcla la
hace el servidor: el cliente dice qué cambia.
- Pantalla «Detalle de oferta»: campos editables, resalte de faltantes, `raw_text`
  plegable y el link de origen.
- El resalte usa una **clase CSS identificable** (el test la consulta). No lo hagas con un
  estilo en línea que no se pueda verificar.
